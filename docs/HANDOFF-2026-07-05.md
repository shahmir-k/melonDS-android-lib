## 3. IN-FLIGHT: dispatcher-in-app fix (task M6.9) — root cause FOUND, verification interrupted

**Root cause (proven by analysis; fix authored):** ABI/layout mismatch. The
LITEV_* macros were `add_compile_definitions()` (directory-scoped): the core
library compiled WITH them, but out-of-tree consumers (the app's JNI target
compiling MelonInstance.cpp, which does `new NDS(...)`) compiled WITHOUT.
LITEV_JIT_DISPATCH adds fields to the A64 `Compiler` (embedded in `ARMJIT`,
the FIRST member of `NDS`) → `sizeof(NDS)` differs → glue allocates the small
layout, core's ctor writes past it → the observed SEGV_ACCERR in
`NDS::NDS → FIFO::FIFO`. Explains headless-works/app-crashes perfectly.

**The fix (UNCOMMITTED, workspace `core/CMakeLists.txt`):** after
`add_subdirectory(src)`, re-export every LITEV_* directory definition as
`target_compile_definitions(core PUBLIC ...)` via
`get_directory_property(COMPILE_DEFINITIONS)` loop. In-tree builds unchanged;
out-of-tree consumers now inherit the macros. (Full comment block in the diff.)

**Also uncommitted:** `app/app/build.gradle.kts` — LITEV_JIT_DISPATCH,
LITEV_LINK_UNCOND/COND/FALLTHROUGH flipped OFF→ON (lines ~62–65).

**Verification stopped at a trivial env issue:** `./gradlew
:app:assembleGitHubProdDebug` failed in `:common:compileKotlin` with
"Inconsistent JVM Target Compatibility" — almost certainly a wrong JAVA_HOME in
the resume shell (previous agents built fine with Homebrew openjdk@21; check
`app-port/gradle13.log` header or `~/.gradle/gradle.properties` for the exact
JAVA_HOME they used). NOT a fix failure.
